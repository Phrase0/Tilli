# 組合與套餐 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓攤商能在管理商品頁建立「套餐」（收銀直接點選）與「組合」（依數量自動換算），結帳時正確攤提、扣庫存，並把交易明細改成可還原套餐／組合的獨立明細頁。

**Architecture:** 套餐／組合以 `[BundleModel]` JSON 存在 `CDEventEntity.bundlesData`。所有計算放在 `Service/` 的純函式元件（驗證、可用性、組合套用、購物車定價、交易還原），ViewModel 只負責接線；寫入邊界（結帳）共用一個 `CheckoutRecorder`。現有 `RevenueAllocator` 擴充為同時寫入 `bundleDiscount`。

**Tech Stack:** Swift / SwiftUI、CoreData（`Tilli.xcdatamodeld`）、XCTest。

**Spec:** `docs/superpowers/specs/2026-10-27-bundles-design.md`（以下簡稱「設計 §N」）。執行者兩份都要讀。

**不在本計畫：** 設計 §8「收銀頁互動調整」（Uber Eats 式增減、訂單摘要可增減、優惠明細新版面）另開計畫。本計畫的結帳畫面只在**現有**版面上加入套餐行、「含組合」小標與組合折抵行（含取消／恢復）。CSV 不改（設計 §7）。

## Global Constraints

- 遵守 `CLAUDE.md`、`CONVENTIONS.md`：金額一律 `MoneyHelper`（不用原生 `+ - * /`）；場次內資料經 `EventDataSource`；共用計算元件只准一份；使用者可見文字走 `Localizable.xcstrings`（lowerCamelCase key，上方註解中文原文）。
- 守衛只准拒絕，不准靜默改做別的事；保護放在寫入邊界。
- 測試：CoreData 用 `TestStore.makeInMemoryContainer()`；**不呼叫任何會碰 `Auth.auth()` 的 Repository 方法**（直接建 `CDxxxEntity` fixture）；mock 放 `TilliTests/TestHelpers.swift` 的 `static func mock(...)`；測試名說出預期行為。
- 改了 CoreData model 或 `ARCHITECTURE.md` §4 後必跑 `python3 scripts/check_field_classification.py`。
- 建置：`xcodebuild -project Tilli.xcodeproj -scheme Tilli -destination 'generic/platform=iOS Simulator' build`
- 單一測試類別：`xcodebuild test -project Tilli.xcodeproj -scheme Tilli -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:TilliTests/<Class>`
- 價格條件（設計 §4.2）：**套餐價 ≤ 成員原價合計**；**組合價 ≤ N × 候選最低單價**；等於上限允許（只提醒「沒有優惠」）。
- 套用順序（設計 §5.3）：**每件平均價（price ÷ N）低者先**；同分時 **N 大者先，再以 `id.uuidString` 升冪**（本計畫的決定，設計 §9 交給建構者）。
- 組合候選單位排序：**單價由高到低**，同價以 `productId.uuidString` 升冪。
- 套餐成員**不計入**組合（組合只看購物車的單點商品行）。
- 攤提順序（計畫書 §7.3）：套餐／組合差額 → 百分比 → 減額 → 捨入（沿用 `RevenueAllocator`）。

## Review Focus

1. **USD 等有小數的幣別**：套餐價 9.99、組合價 25.50 時，Σ `actualRevenue` 仍等於 `totalAmount`、`bundleDiscount` 加總等於差額 —— Task 6 加 `testUSDBundleAndComboStillReconcileToTotal`。
2. **第 5 批之前的舊交易**（沒有 `bundleDiscount`／`bundleKind`）在新明細頁仍能顯示且恆等式成立 —— Task 12 加 `testLegacyTransactionWithoutBundleFieldsStillReconciles`。
3. **成員所屬類別被停用**（商品本身沒下架）：套餐要灰掉並顯示原因，不可只看 `product.isDisabled` —— Task 4 加 `testFixedBundleUnavailableWhenMemberCategoryDisabled`。
4. **同一商品出現在兩列**（部分被組合涵蓋、部分沒有，或單點＋套餐成員）：結帳扣庫存要**累加**，不可覆蓋（現行 `stockUpdates[id] = stock − qty` 會覆蓋）—— Task 7 加 `testStockUpdatesAccumulateRowsOfSameProduct`。
5. **套餐已被刪除**後，歷史明細仍以快照名稱與價格顯示 —— Task 12 加 `testDeletedBundleStillRendersFromSnapshot`（breakdown 不讀場次設定）。

### Task 4: 購物車與套餐可用性

**Files:**
- Create: `Tilli/Model/Domain/Cart.swift`、`Tilli/Service/BundleAvailability.swift`
- Test: `TilliTests/BundleAvailabilityTests.swift`

**Interfaces:**
- Produces:
  ```swift
  struct BundleCartLine: Hashable {
      var quantity: Int
      let nameAtAdd: String
      let priceAtAdd: Decimal
      let productIdsAtAdd: [UUID]
  }
  struct Cart: Equatable {
      var productQuantities: [UUID: Int] = [:]
      var bundleLines: [UUID: BundleCartLine] = [:]     // key = bundle id；一個套餐一行
      var cancelledComboIds: Set<UUID> = []
      /// 此商品已被購物車佔用的數量 = 單點數量 + Σ 含此商品的套餐行份數
      func reservedQuantity(of productId: UUID) -> Int
      var isEmpty: Bool { get }
  }
  enum BundleUnavailableReason: Error, Equatable {   // Error：才能放進 Result
      case bundleDisabled
      case memberMissing
      case memberUnavailable(productName: String)     // 商品下架或類別停用/不存在（用 saleAvailability）
      case memberOutOfStock(productName: String)
  }
  enum BundleAvailability {
      /// 可再加入的份數；不可賣時回傳原因。`cart` 用來扣掉已佔用的庫存（雙向佔用，設計 §5.6）。
      static func check(_ bundle: BundleModel, products: [UUID: ProductModel], categories: [CategoryModel], cart: Cart) -> Result<Int, BundleUnavailableReason>
      /// 單點商品還能再加幾個（stock − reservedQuantity）
      static func remainingStock(of product: ProductModel, cart: Cart) -> Int
      /// 回到收銀頁時重新驗證（設計 §9.1 第 5 點）
      static func invalidLines(in cart: Cart, bundles: [UUID: BundleModel], products: [UUID: ProductModel], categories: [CategoryModel]) -> [InvalidBundleLine]
  }
  struct InvalidBundleLine: Equatable {
      let bundleId: UUID
      let name: String           // 用 nameAtAdd，套餐已刪除也能顯示
      let reason: InvalidBundleReason
  }
  enum InvalidBundleReason: Equatable { case deleted, disabled, priceChanged, membersChanged, unavailable(BundleUnavailableReason), insufficientStock }
  ```
- `check` 的份數 = min over 成員 (`product.stock − cart.reservedQuantity(of:)`)；份數 ≤ 0 → `.memberOutOfStock`（取第一個不足的成員名）。

### Task 5: 組合自動套用 `ComboApplier`

**Files:**
- Create: `Tilli/Service/ComboApplier.swift`
- Test: `TilliTests/ComboApplierTests.swift`

**Interfaces:**
- Consumes: `Cart`、`BundleModel`、`ProductModel`、`isAvailableForSale(in:)`。
- Produces:
  ```swift
  struct ComboApplication: Equatable {
      let bundleId: UUID
      let name: String
      let groupCount: Int
      let coveredQuantities: [UUID: Int]   // productId → 被此組合涵蓋的數量
      let deduction: Decimal               // Σ(每組原價合計 − 組合價)
  }
  enum ComboApplier {
      /// 只看 cart.productQuantities（套餐成員不計入）；排除 cancelledComboIds、isDisabled、非 chooseAny 的 bundle；
      /// 不可販售（isAvailableForSale == false）的候選不計入。回傳順序 = 套用順序。
      static func apply(cart: Cart, combos: [BundleModel], products: [UUID: ProductModel], categories: [CategoryModel]) -> [ComboApplication]
  }
  ```
- 演算法（Global Constraints 的兩個排序）：單位展開 → 依序處理每個組合 → 從尚未被使用的候選單位中依排序取，每滿 N 個成一組 → 不足 N 不套用。
